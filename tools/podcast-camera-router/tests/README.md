# בדיקת פרק מלא

הבדיקות הקטנות (30–90 שניות) לא תופסות את מה שנשבר בפרק אמיתי:
סחיפת שעונים לאורך שעה, זיכרון שמצטבר, ואריזה שנחנקת בסוף. לכן
הבדיקה כאן היא על פרק שלם בפרופיל של הלקוחה — 53 דקות, שתי מצלמות
1080p ושני מיקרופונים WAV סטריאו של 609MB.

## הכנה

```bash
pip install av numpy imageio-ffmpeg
mkdir -p /work/ep
node gen-mics.js          # שני WAV של 609MB, תור דיבור של 19.7ש׳
bash gen-cams.sh          # שתי מצלמות 1080p30, כ-45 דקות קידוד
```

מצלמה 1 נוטה לאדום, מצלמה 2 לכחול — כך אפשר לזהות מהפיקסלים מי על
המסך. דוברת 1 מדברת ב-220Hz ודוברת 2 ב-430Hz — כך אפשר לזהות מהקול
מי אמורה להיות. **במצלמה 2 מוזרקת סחיפת שעון אמיתית של 0.02%**
(0.63 שניות לאורך הפרק), כדי שתיקון הסחיפה באמת ייבדק.

## ריצה

```bash
node run-episode.js /path/to/index.html /work/out
python3 measure.py /work/out/episode.webm
```

## מה נמדד

| שדה | משמעות |
|---|---|
| `videoFrames` / `fps` | האם הקובץ מלא ובקצב אחיד |
| `dupFrames` / `longestFreezeSec` | תקיעות — פריים כפול = תמונה קפואה |
| `uniqueFps` | תנועה אמיתית, לא מצגת שקופיות |
| `offStd` | פיזור הסנכרון תמונה-מול-קול |
| `drift` | הפרש בין תחילת הפרק לסופו — הסחיפה |
| `perFifth` | הסטייה בכל חמישית — תופס בעיה שמופיעה רק באמצע |

`offMean` שלילי קבוע הוא תקין: החיתוך נוחת מעט לפני שהדוברת מתחילה,
בכוונה. מה שחשוב הוא `offStd` ו-`drift`.

## בדיקות רגרסיה

```bash
node test-mp4pack.js                    # אורז ה-MP4 — הנתיב של הלקוחה
node test-audio.js ../index.html /work/fx44    # מיקרופון 44.1kHz
node test-audio.js ../index.html /work/fxmp3   # מיקרופון דחוס
node test-failure.js                    # כשל באמצע: דיווח + קובץ חלקי
```

`test-mp4pack` חשובה במיוחד: לכרום בסביבה הזאת אין H.264 כלל — לא
קידוד ולא פענוח — ולכן שום בדיקה מקצה-לקצה לא נוגעת בפורמט שהלקוחה
מקבלת בפועל. הבדיקה מזרימה דגימות H.264 אמיתיות עם B-frames דרך
פונקציות האריזה של הדף עצמו ומשווה מול pyav.
